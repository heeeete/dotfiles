# 업무 가이드 영상

**유일한 제작 기준은 [사용자가 승인한 최종 영상](assets/approved-motion-voice.mp4)**이다. 사용자는 이 영상의 자연스러운 움직임과 개선된 음성을 승인하고 앞으로도 같은 방식으로 제작하기를 요청했다. 새 요청에서 명시한 변경은 우선한다.

## 반드시 유지할 것

- **실제 연속 녹화:** 실행 중인 서비스의 전체 화면을 촬영한다. 캡처를 이어 붙이거나 정지 이미지에 줌·팬을 넣어 본문을 대신하지 않는다. 메뉴·카드·모달을 재구성하거나 제품 소스·CSS를 촬영용으로 바꾸지 않는다.
- **자연스러운 흐름:** 안내 → 대상 강조·커서 이동 → 실제 클릭·입력 → 결과 확인이 이어져야 한다. 실제 화면 전환을 남기고 불필요한 로딩·대기만 줄인다. 읽는 동안의 멈춤은 허용하며, 장면마다 고정 시간을 배정하지 않는다.
- **커서 하나:** 작은 반투명 붉은 생성 커서와 실제 클릭 순간의 파동만 표시한다. 시스템·자동화 도구의 검은 커서를 함께 녹화하지 않는다. 이동과 클릭은 같은 입력 방식과 좌표계를 사용한다.
- **음성:** Microsoft `ko-KR-SunHiNeural`, 속도 `-5%`, 기본 pitch·volume을 사용한다. macOS `say`/Yuna 등 운영체제 기본 음성으로 대체하지 않는다. 배경음·효과음은 추가하지 않는다.

## 화면 스타일

- 시작과 끝에 파란 그라데이션 카드, 흰 제목, 작은 분류·짧은 설명을 중앙 정렬한다. 시작은 읽을 만큼, 끝은 짧게 보여준다.
- 자막은 하단 중앙의 문장 길이에 맞는 둥근 짙은 회색 패널과 흰 글자다. 번호 없이 짧은 해요체로 쓰고 실제 메뉴 이름을 정확히 표기한다. 필요한 보조 설명만 작고 옅게 덧붙인다.
- 포커스는 둥근 노란 테두리와 은은한 주변 암막이다. 설명 대상이 바뀌면 실제 요소를 다시 추적하고 커서를 강제로 이동시키지 않는다.
- Pretendard를 우선 사용한다. 원본 화면의 비율과 배치를 유지하고 오버레이만 비례 조정한다. 승인 영상의 길이·해상도·업무 내용을 모든 영상에 고정하지 않는다.

## 제작과 전달

1. 승인 영상을 확인하고 [촬영 지침](references/recording.md)을 읽는다. 스타일과 보이스는 다시 묻지 않는다. 실제 기능을 확인한 뒤 요청한 업무의 짧은 대본을 작성한다.
2. 짧게 시험 녹화해 이동 중·클릭 전후에 검은 커서가 없고, 붉은 커서가 실제 대상과 일치하는지 확인한다. 안내 음성을 먼저 확보하고 장면 시간을 맞춘다.
3. 실제 화면을 연속 녹화한다. [오버레이 CSS](assets/guide-overlay.css)와 [오버레이 모듈](assets/guide-overlay.mjs)을 재사용한다. 이 자산은 촬영용 레이어이며 업무 동작·녹화·음성 합성을 대신하지 않는다.
4. 최종 MP4의 화면·음성·자막 동기화와 완료 상태를 검수한다. 처음부터 끝까지 실제 속도로 재생하는 것이 원칙이다. 재생·청취가 불가능하면 수행한 검수 범위만 정확히 알린다.
5. H.264/AAC MP4와 SRT를 제공하고 촬영 코드·실제 타임라인·음성 파일·대본을 산출물에 보관한다. 답변에는 영상 미리보기와 다운로드 링크를 간단히 제공한다.

실제 화면에 접근할 수 없으면 녹화나 접근 경로를 요청한다. 승인 영상 속 업무·고객 정보를 새 영상의 샘플 데이터로 복사하지 않는다. 촬영 요청을 실제 업무 데이터 변경이나 외부 연락 권한으로 해석하지 않는다. 샘플 데이터가 필요하면 격리된 환경에서 준비하고 실제 서버에 변경 요청이 나가지 않게 한다. 사용한 화면이 로컬인지 배포본인지, 샘플 데이터인지 정확히 알린다.

기본 보이스를 사용할 수 없으면 동급 신경망 음성 샘플을 준비해 변경 사실을 알린다. 음성 제작 자체가 불가능하면 한계를 알리고 무음 영상을 완성본으로 임의 대체하지 않는다. 사용자가 지정한 음성·무음 요청은 우선한다.
