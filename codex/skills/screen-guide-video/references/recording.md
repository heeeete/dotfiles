# 승인본 재현을 위한 촬영 지침

기준은 [최종 승인 영상](../assets/approved-motion-voice.mp4) 하나다. 아래는 해당 영상의 커서·연속 녹화·음성을 재현하는 데 필요한 절차다.

## 화면과 오버레이

현재 환경에서 허용된 브라우저·녹화 도구와 설치된 FFmpeg를 확인한다. 기기 경로나 과거 브라우저 ID를 복사하지 않는다. 앱·폰트·초기 데이터 로딩이 끝난 뒤 유효 촬영을 시작하고, 촬영 중 viewport를 유지한다.

[CSS](../assets/guide-overlay.css)와 [모듈](../assets/guide-overlay.mjs)의 카드·자막·포커스·붉은 커서를 재사용한다. CSS의 기준 치수는 오버레이 비례 계산용이며 출력 해상도를 강제하지 않는다. 자막이 버튼·결과를 가리면 위치를 조정하고, 모달 암막 위에서는 추가 포커스의 dim을 줄인다. 포커스 대상이 사라지면 해제한다.

모듈의 Playwright wrapper는 로컬 Playwright가 허용되는 격리 환경용이다. 연결된 사용자 Chrome에서는 현재 브라우저 도구와 CDP capability 문서를 읽고 지원되는 API로 같은 레이어를 설치·제어한다. 제품 소스는 수정하지 않으며 사용자 브라우저에 우회 연결하거나 인증 정보를 복사하지 않는다.

## 붉은 커서만 촬영하기

승인본은 연결된 Chrome에서 **이동·누름·뗌 모두 `Input.dispatchMouseEvent`**로 통일했다. 이동만 CDP로 하고 클릭은 브라우저 도구의 `locator.click()`으로 처리하는 조합은 사용하지 않는다.

1. 현재 보이는 DOM에서 대상 중심의 viewport CSS 픽셀 좌표를 구한다. 스크롤·레이아웃 변경 후 다시 구한다.
2. `mouseMoved`를 시간 간격을 두고 보내 목적지로 가감속 이동한다. 승인본은 24단계, 단계 사이 약 24ms, 보간식 `t*t*(3-2*t)`를 사용했다. 거리와 맥락에 맞게 조절한다.
3. 같은 좌표에서 `mousePressed`, 약 80ms 뒤 `mouseReleased`를 보낸다. 두 이벤트 모두 `button: 'left'`, `clickCount: 1`을 쓴다. 실제 `pointerdown`이 오버레이의 클릭 파동을 만든다.
4. 현재 UI를 다시 읽어 실제 결과를 확인한다. 포커스 변경으로 커서를 순간이동시키거나 효과만 표시하고 클릭을 생략하지 않는다.

검은 화살표가 녹화되면 입력 방식·캡처 설정을 고친다. 서비스 CSS나 화면 위 덧칠로 숨기지 않는다. 다른 허용된 촬영 도구를 쓰더라도 이동 중·클릭 전후에 붉은 커서 하나만 보이는지 먼저 검증한다.

## 실제 연속 녹화

승인본은 `Page.startScreencast`의 실제 브라우저 프레임 스트림을 JPEG quality 90, `everyNthFrame: 1`로 수집했다. 개별 스크린샷을 낮은 빈도로 찍어 이어 붙이는 방식으로 대체하지 않는다.

- `Page.screencastFrame`을 즉시 수집하고 각 sessionId에 `Page.screencastFrameAck`를 보낸다. 이벤트 cursor를 갱신하고 누락·truncated 여부를 확인한다.
- 수집 루프와 UI 액션을 같은 도구 호출 안에서 실행하고 둘 다 await한다. 백그라운드 Promise를 남긴 채 호출을 끝내지 않는다.
- 프레임 `metadata.timestamp` 차이로 실제 재생 간격을 보존한다. 정지 화면에서 이벤트가 줄면 다음 프레임 시각까지 유지하고, 마지막 카드도 실제 녹화 종료 시각까지 유지한다. 움직이는 구간의 프레임 누락을 반복 프레임으로 숨기지 않는다.
- 녹화 시작과 첫 프레임 timestamp의 차이를 음성·SRT에 반영한다. 출력은 승인본처럼 30fps로 인코딩하되 실제 동작 속도를 바꾸지 않는다.
- 종료·실패 시 finally에서 녹화 중지, 수집 종료, 설치한 오버레이·이벤트 리스너 제거를 수행한다.

클릭·메뉴 전환·입력·스크롤·결과가 이어지게 녹화한다. 입력은 실제 타이핑을 보이고, 스크롤은 부드럽게 한다. 안내가 실행보다 먼저 나오게 하고, 불필요한 대기는 동작이 끝난 안정된 지점에서 줄인다. 매 행동마다 컷·디졸브·줌을 넣지 않는다.

## 한국어 신경망 음성

승인 설정은 **edge-tts / `ko-KR-SunHiNeural` / rate `-5%` / 기본 pitch·volume**이다. 설치된 도구를 확인하고 필요하면 허용된 임시 Python 환경에 설치한다. 사용법은 [edge-tts 프로젝트](https://github.com/rany2/edge-tts)를 참고한다.

명령 옵션은 `--voice ko-KR-SunHiNeural --rate=-5% --text <장면 대본> --write-media <출력.mp3>`이다. 합성 서비스에는 필요한 안내 대본만 보내며 화면·계정 정보·업무 데이터는 보내지 않는다.

장면별로 합성해 실제 오디오 길이와 소리 유무를 확인한다. 파일 생성만으로 성공으로 판단하지 않는다. 음성을 자막 시작 시각에 맞추고, 다음 안내나 음성과 겹치면 대본·장면 시간을 조정한다. 음성을 맞추기 위해 정지 캡처를 끼우거나 실제 동작을 과도하게 느리게 하지 않는다.

## 출력과 확인

H.264, yuv420p, AAC 128kbps, faststart MP4로 출력한다. 영상 품질은 CRF 18을 시작점으로 사용한다. 프레임의 폭·높이가 홀수면 필요한 최소 패딩만 적용한다. 원본 비율을 바꾸거나 임의 색 보정을 하지 않는다.

별도 음성을 실제 타임라인에 맞춰 합친 뒤 apad로 끝까지 패딩하고, 실제 편집 영상 길이를 `-t`로 지정한다. 마지막 말이 영상 끝을 넘지 않는지 먼저 확인한다. 짧은 음성 때문에 엔딩이 잘리거나 무한 패딩 출력이 되지 않아야 한다.

최종 확인 항목:

- 이동·클릭 전후에 검은 커서가 없고 붉은 커서 하나가 실제 클릭 지점과 일치한다.
- 자막이 대상·결과를 가리지 않고 안내 → 행동 → 결과 순서가 맞는다.
- 음성·자막이 해당 장면과 일치하며 서로 겹치거나 잘리지 않는다.
- 연속 동작, 시작·마무리 카드, 완료 상태가 출력 MP4에 남아 있다.
- 전체 디코딩, 해상도·비율, 오디오 스트림·실제 소리를 확인한다. 실제 속도 재생·청취를 못 했으면 완료했다고 주장하지 않는다.
