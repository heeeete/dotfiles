# PR 리뷰 요청 메시지 작성

현재 PR을 빠르게 이해할 수 있는 한국어 리뷰 요청 메시지를 작성한다.

## 확인 절차

1. 사용자가 PR 번호나 URL을 지정하면 해당 PR을 사용한다.
2. 별도 지정이 없으면 현재 저장소와 브랜치에 연결된 PR을 찾는다.
3. PR 제목과 본문뿐 아니라 대상 브랜치 대비 실제 변경 내용도 확인한다.
4. 변경 이유, 달라진 동작, 유지되는 기존 동작, 리뷰어가 알아야 할 핵심을 선별한다.
5. PR을 찾을 수 없거나 제품 의도를 판단할 정보가 부족할 때만 사용자에게 질문한다.

PR과 저장소는 읽기 전용으로 확인한다. PR 본문 수정, 댓글 작성, 커밋, 푸시 등 외부 상태를 변경하지 않는다.

## 작성 형식

다음 구조를 기본으로 사용하되, 변경 규모에 맞춰 문단과 항목 수를 조절한다.

```text
PR : [PR 제목](pr link)

<자연스러운 리뷰 요청 문장>

<변경 배경과 핵심 동작 설명>

작업 내용
- <핵심 변경>
- <핵심 변경>
```

API 엔드포인트를 본문에 적었다면 메시지 마지막에 각 API의 역할을 덧붙인다.

```text
API 역할
- `/example/path`: 이 API가 담당하는 역할
```

## 작성 원칙

- 한국어로 자연스럽고 직접적으로 작성한다.
- 첫 줄에는 실제 PR 제목을 `PR : <제목>` 형식으로 적는다.
- 파일별 변경 목록은 피하되, 추상적인 표현보다 실제 구현 방식과 그 효과를 직접 설명한다.
- 간단한 변경은 짧게, 복잡한 변경은 이해에 필요한 만큼 설명한다.
- 작업 내용을 억지로 특정 개수에 맞추지 않고 의미 있는 변경 축만 고른다.
- API 엔드포인트를 적을 때는 정확한 경로를 사용하고 임의의 별칭으로 대체하지 않는다.
- API가 등장하지 않는 PR에는 `API 역할`을 추가하지 않는다.
- 확인할 수 없는 동작이나 수치를 추측하지 않는다.
- 최종 메시지 전체를 네 개의 백틱으로 시작하고 끝나는 `md` 코드 블록으로 감싸 Markdown 원본으로 출력한다.
- 사용자에게 전달할 리뷰 요청 메시지만 출력하고 작업 과정은 덧붙이지 않는다.
